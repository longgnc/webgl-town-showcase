# 参考还原与资产交接

## 按输入条件选方法

口述：提炼主题、尺度、时间、天气、色彩和重点。可合理补足街巷与生活细节，但明确属于创作。单图：对齐焦距、地平线、消失点、轮廓与明暗，画外部分不可确定。视频：建立时间码和镜头表，挑选同一物体不同角度、转弯与遮挡展开的帧，区分镜头运动与物体运动。不要把视频压缩噪声当材质细节。

只有单段视频时无法精确知道背面、真实尺度、材质参数和隐藏空间。能完成观感相似的可漫游解释，不等于恢复原工程。多视角照片/视频、实测尺寸或平面图显著提高还原度。必要时使用摄影测量，但水面、玻璃、反光和细叶容易失败。

## 建议用户提供的文件（按价值排序）

1. 原始 FBX/GLB/Blend 或原引擎场景，加全部外链贴图；单独 FBX 通常不足以还原材质。
2. BaseColor、Normal、Roughness、Metallic、AO、Emissive，说明通道打包和法线 OpenGL/DirectX 约定。包括 HDRI、LUT、地形高度图（若有）。
3. 地形、建筑、道具、植被分别命名；保留世界坐标/单位。地面标高、地图边界、人的高度、门宽等至少一个可靠尺寸。
4. 多角度截图、未经平台二次压缩的原视频、关键时间码，以及最需要保留的 3–5 个镜头。
5. 原灯光的位置/颜色/强度、时间/天气、相机 FOV、曝光、后处理设置；能提供工程则优先读工程。
6. 动画骨架与动作、循环音频、音源位置、碰撞与不可进入范围、目标设备和可接受下载大小。
7. 素材授权与使用范围，避免把第三方付费资产无意打包公开。

## FBX → 网页工作流

在 Blender 导入 FBX，核对单位、朝向、负缩放和变换；与 1.7 m 人体参照比较。整理重复材质、UV 和贴图链接；需要保留的程序材质烘焙为 PBR 图。清理内部不可见面和过密曲面，保留重要轮廓。创建简化碰撞与 LOD。按街区/建筑模块拆包，不必一个 GLB 包整座镇。

导出 GLB（glTF 2.0），检查 Principled BSDF 的可导出通道。导入网页后再次核对贴图颜色、法线方向、透明/双面、阴影和动画。GLTFLoader 与 Three 核心固定同版本；不能混用未知 CDN latest。若使用 Draco/Meshopt/KTX2，解码器也要打包，本地离线不能依赖隐含 CDN。

加载示意（需已具备对应版本依赖）：

```js
const loader = new GLTFLoader();
const gltf = await loader.loadAsync('./assets/tea-house.glb');
gltf.scene.traverse(o => {
  if (o.isMesh) { o.castShadow = true; o.receiveShadow = true; }
});
scene.add(gltf.scene);
```

上述代码不会自动建立角色碰撞、导航、LOD 和材质优化，这些需单独完成。当前程序化古镇示例没有提供运行时 FBX 导入按钮；加入模型时按此流程扩展，不应声称现有示例已经具备任意格式导入。

## 相似度的验收维度

先比较镜头姿态和焦距，然后比较主要几何投影、尺度、遮挡、明暗分布、色彩、材质频率，最后看小道具。锁定曝光与时间，避免每轮截图条件变化。将“可证实来自参考”和“补全设计”分开记录。用户若说要 100%，解释输入缺失限制，并用逐镜头/逐资产清单将目标变得可检验，不做绝对保证。
