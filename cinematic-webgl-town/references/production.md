# 场景制作流程与技术决策

## 1. 把描述转成可制作的设计

为口述场景写一页 brief：时代/地域、天气/时间、主色、尺度、人类活动痕迹、地标、叙事和移动方式。例如江南水镇的视觉语法是白灰粉墙、深灰瓦、棕黑木构、窄巷、贴水建筑、石桥、沿河生活；不能混成任意寺庙模型的堆积。

把艺术方向落实到数字：人物眼高 1.65–1.75 m，门宽约 0.9–1.4 m，门高约 2–2.5 m，民居层高约 2.8–3.5 m。建筑、台阶、河宽和桥跨度必须在同一尺度下。尺寸区间是设计起点，不代表文保测绘。

镇级空间先规划水系与街道，再放建筑。建议主河贯穿、桥间距有变化，沿河步道、集市、庙前广场、后巷、外围林地形成不同节奏。每条街应有目的地或回环，尽量避免所有道路都是等宽棋盘格。主地标可远望，近景要有遮挡与展开。

## 2. 几何与资产组织

灰盒阶段只用箱体和简单坡面，先确定路线与镜头。以人在地面的视角验证，不只看俯视图。前景 0–20 m 是细节投资重点，中景 20–100 m 负责轮廓和立面，远景依靠简化轮廓和雾。

建筑模块分地基、墙、木框、门窗、屋顶、装饰。不要整体缩放房子制造变化；改变开间数量、层数、屋面高、院落结构、店面、退界和材质状态。屋顶需要弯曲檐线、脊线、端盖、厚度与压暗檐底。可用参数化 BufferGeometry 构造屋面，批处理瓦垄/椽头。真实瓦片逐个放置只保留近景样板。

桥的可见拱洞与上表面必须匹配。行走用连续高度函数或碰撞网格，上表面不能在视觉坡面下方。岸边需要挡墙、低栏、码头台阶和水位线。空间规划提前留下通行宽度，装饰不得堵住桥头。

重复零件用 InstancedMesh；整镇按约 32–80 m 空间块归组，使视锥裁剪有效。同材质静态零件可合并，但避免把全部地图合成一个无法裁剪的网格。每个实例组检查 boundingBox / boundingSphere。碰撞几何独立于装饰几何，静态 AABB 可用网格哈希加速。

## 3. 材质

基础 PBR 通道：baseColor、normal、roughness、metalness，可加 AO。颜色图用 sRGB，法线/粗糙度/AO 为数据，不能做 sRGB 解码。石头、木头、灰泥大多非金属；湿石降低粗糙度并稍微压暗，不能把一切设成镜面。

同一材质至少有宏观颜色变化、中频拼缝/木纹、微法线三个层次。纹理按世界米数重复，不让长墙纹理拉伸。墙脚潮痕、窗沿积灰、石缝苔藓符合环境逻辑。Canvas 可生成纹理，Shader 可计算噪声/湿润；这些节省下载体积，但消耗启动时间、显存和 GPU。固定种子确保复现。

检查贴图接缝、法线强度、重复频率；近景放一两个独特物件打破重复。没有贴图素材时程序纹理是有效选择，但不要将其描述为扫描级细节。

## 4. 光照、环境、后处理

以一盏方向光为主光，搭配天空/半球/环境贴图。选择暖主光与冷阴影等明确关系，但不强制橙青滤镜。阴影相机围绕人物附近，覆盖整个镇会浪费分辨率；大范围使用级联或局部更新。薄几何检查 shadow bias，过大导致悬浮，过小导致条纹。

工作流是线性光照 → HDR 目标（可用时）→ AO/反射/体积效果 → bloom → 色调映射 → sRGB 输出。具体库可合并 pass，但避免重复色调映射或 sRGB 转换。Bloom 只强调亮部，暗角保持克制。参考原件包含自定义天空、柔影、AO、体积光、反射和后处理，复制其全部效果需要处理各自场景边界，不能只照抄参数。

天空可程序生成云层与太阳；可用 PMREM 环境图提供材质反射。水采用平面反射摄像机或 SSR/环境反射，Fresnel 控制掠射角。平面反射相机要镜像位置与朝向，裁掉水下几何，避免把水面自身再次反射。低档允许环境近似，必须标注质量差异。

## 5. 环境动态和声音

植被顶点风动应以根部为零、顶部为强；分株相位打散。柳枝摆动缓慢，叶片颤动频率较高。旗布在挂点固定。水位不随每个碎片乱跳。粒子使用相机周边池，不为整镇生成百万雨点。

Web Audio 需要点击后 resume。程序噪声经滤波可产生风/水/脚步，但真实录音更适合高保真鸟鸣、人声和乐器。音效循环做无缝或交叉渐变；不要每帧创建节点。空间声源按距离衰减，监听者跟随相机，多个河段使用最近点而非单个远方音源。静音、暂停、失焦、恢复都验证。没有试听证据时只报告节点状态，不声称听感验收。

## 6. 性能预算

首先记录机器、浏览器、窗口和 DPR。桌面起点可采用 1–1.5 DPR、2K 阴影、半分辨率反射；弱设备降反射频率、粒子和阴影后再降主画面分辨率。高档不是盲目 4K。

记录 CPU 构建时间、帧时中位与 P95、draw calls、可见三角形、纹理数、几何数。文件小不等于显存小：1024² RGBA 约 4 MiB，带 mipmap 约 5.33 MiB。几百 MB 的运行时场景可由几十 KB 规则生成。

先定位瓶颈：高 draw calls 用实例与合并；GPU fill rate 用降分辨率/透明层；阴影用缩范围和更新频率；构建卡顿分批生成；碰撞 CPU 用空间索引。不要以降低所有细节作为唯一优化。

## 7. 软件准备

必需：支持 WebGL2 的现代桌面浏览器、代码编辑器（VS Code 等）、本地文件或静态服务。构建项目可使用 Node.js；简单页面不需要框架。Blender 用于建模、重拓扑、UV、烘焙、FBX 导入和 GLB 导出。用户已有 3ds Max/Maya 也可作为建模入口。Substance Painter/Designer 可选，用于 PBR 绘制；GIMP/Photoshop 可选，用于贴图处理；Audacity 可选，用于声音剪辑。不要为了运行纯前端项目要求用户安装 Unity 或 Unreal。
